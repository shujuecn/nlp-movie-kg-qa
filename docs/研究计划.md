## 2. 背景与目标

上一课的 bge 句向量只用于分类和回归，它最自然的下一站是检索。本课走完整条
**采集豆瓣周星驰电影 → 三元组抽取 → NetworkX 知识图谱 + FAISS 向量索引 → 混合问答 → Gradio 工作台 → 评测**，
并把"什么放本地、什么走 API"作为明示教学内容：embedding / 图谱 / 检索 / 前端全部本地跑（CPU 即可，
无独立显卡要求），理解与生成类任务走 silra API。

交付物：可运行、可分发、有指标的教学仓库 + Gradio 问答工作台 + 课后作业文档。

## 3. 探查结论（2026-11-07 当天实测）

### 3.1 豆瓣可达性（与 v1 差异大，以本节为准）

- **搜索列表页** `search.douban.com/movie/subject_search?search_text=<词>&start=<n>`：免登录，requests 可达。
  - 源码 `window.__DATA__` 是**明文 JSON**（用 `json.JSONDecoder().raw_decode` 解析），含
    `count / start / total / items`；item 带 id、title、url、abstract 等；每页 15 条，`start` 步进翻页。
  - 搜"周星驰" `total=126`，混有 1 条人物卡（"周星驰 Stephen Chow"，无年份）和未上映条目（《功夫女足2》2030）。
    过滤规则：丢弃无 `(年份)` 后缀的人物卡；保留年份 ≤ 2026 的电影条目；入库时再按详情页导演/主演复核。
    人物卡不浪费：abstract 含英文名（Stephen Chow）与代表作列表，进实体别名表素材。
- **单片详情页** `movie.douban.com/subject/<id>/`：已收紧，三段实测：
  1. requests 直连 → 302 跳 `sec.douban.com/c?r=...`，带随机 `bid` cookie 仍 403；
  2. 未登录真实浏览器 → 安全页提示 `error code: 01004 Please login`；
  3. **登录态浏览器正常渲染**（应用内浏览器实测《功夫》）：`#info`（导演/编剧/主演/类型/制片国家/地区/
     语言/上映日期/片长/又名/IMDb）、`strong[property=v:average]` 评分、`span[property=v:votes]` 人数、
     `span[property=v:summary]` 剧情简介全文，字段齐全。
- **采集方案**：列表走 requests（快、可断点、免登录）；详情走登录态浏览器逐页采集——
  备课期由 Agent 驱动浏览器完成（本会话已验证通道、登录态现成），限速 3-5 秒 + 抖动；
  学生复现走两条路：在自己的 Agent Harness 里登录一次再采（与 261101 作业同款工作方式），
  或 playwright 复用 storage_state（261101 作业任务一已练过）。

### 3.2 silra API（当天实测）

- Base URL `https://api.silra.cn/v1`，OpenAI 兼容；帮助文档 <https://silra.apifox.cn/>，定价页为 JS 渲染。
- `/v1/models` 返回 36 个模型；**`qwen3.8-flash` 在列**（备选 `qwen3.8-27b` / `qwen3.5-flash` / `qwen-plus`）。
- `response_format: {"type": "json_object"}` 结构化输出实测通过（电影/人物抽取任务返回合法 JSON）。
- Key 管理：写入本地 `.env`（`SILRA_API_KEY`），`.env` 进 `.gitignore`，仓库只附 `.env.example`；
  文档与代码一律不出现明文 key。

### 3.3 本机环境

- torch-env：Python 3.11、openai 已装；v2.1 后本地无深度学习依赖（torch/sentence-transformers 不再需要）。
- Embedding 走 SiliconFlow API `Qwen/Qwen3-Embedding-8B`（实测：dimensions=1024 可用、批量可用、
  返回已归一化向量，成本每千次请求几分钱级）；261101 的本地 bge 权重不再使用。
- 需新装：`gradio`、`networkx`、`faiss-cpu`、`python-dotenv`（已装齐）。磁盘充足。
- 工具链：ruff 在 torch-env、mypy 在 base。

## 6. 关键设计

- **三元组 schema**：`(head, head_type, relation, tail, tail_type, source)`；relation 覆盖
  导演/编剧/主演/类型/制片地区/语言/上映年份/片长/评分/又名/饰演/题材主题；`source` 标注
  `douban-info`（确定性解析）/ `llm-offline`（离线抽取）/ `llm-live`（课堂现场演示）——数据来源本身是讲解素材。
- **语义三元组**（离线，每部 3-6 条）：重点是"角色-饰演者"对齐（阿星→周星驰、紫霞仙子→朱茵，
  可答"紫霞仙子是谁演的"）与题材主题；生成后按作业规矩抽查 10 条再定稿。
- **问答流**：
  1. 问题理解（API，JSON）：实体提及、问题类型（事实 / 概述 / 推荐 / 超范围）、目标关系；
  2. 实体链接：别名精确 → 子串 → 向量余弦兜底；
  3. 检索与作答：事实题走图谱谓词查询 → **模板直答**（本地、零成本、毫秒级）；
     概述/复杂题把图谱子图序列化 + FAISS 简介片段拼上下文 → **RAG 生成**（API，要求引用证据）；
  4. 兜底：图谱外问题礼貌说明能力范围；**无 key 降级模式**：跳过 API 环节，模板直答 + 证据面板直接展示检索结果，
     保证仓库零 key 也能跑通主干（延续 v1"克隆即可跑通"的底线）。
- **教学连续性**：向量模型由上一课的本地 bge 升级为 API 版 Qwen3-Embedding-8B，
  正好对照"本地推理 vs API 服务"的工程取舍；261101 作业学生已登录爬过"自己那部电影"的评论，
  本次作业把同一部电影的**详情页**补进图谱，两课串成一条线。
- **指标**：`eval` 子命令输出实体链接命中率、答案关键词命中率、生成题引用有效率，延续"每课可度量"。

1. 脚手架：移植 261101 的 config.py 模式与 requirements / pyproject / .gitignore（kg/、eval/ 不忽略）。

## 8. 验证方案

端到端：`ingest` → `build-kg` → `index` →
`ask -q "功夫是谁导演的"`（模板直答）→ `ask -q "紫霞仙子是谁演的"`（语义三元组）→
`ask -q "介绍一下大话西游"`（RAG 生成，检查引用）→ 一道超范围问题（礼貌兜底）→

## 9. 边界与风险

- 爬虫：仅 ~60 部详情页、限速礼貌采集、数据课程自用；movies.jsonl（含简介全文）与 raw 快照
  随仓库分发，仅教学使用；若仓库转公开，数据包改为私下分发。
- API 成本：离线抽取全程约 10 万 token 量级（几分钱级）；在线问答单次 2-4k token；
  学生用各自兑换的 key，单次作业预算可控制在 1 元内。备课用 key 已出现在会话记录中，正式开课前建议轮换。
- 登录态：应用内浏览器的登录态随进程存续，重开会话需重新登录；学生复现走 playwright storage_state
  或在自己的 Agent 会话里登录。
- 豆瓣风控可能再收紧：列表页明文 JSON、详情页登录门槛均为 2026-11-07 快照，采集模块保留断点续爬与降级路径。
- gradio 与 261101 webapp 同用 7860 端口，不要同时开。
- 教学讲稿不在本项目范围，系统跑通后另行准备。
