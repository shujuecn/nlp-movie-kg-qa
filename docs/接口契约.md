## 2. 数据文件 schema

- 原始记录 `data/raw/<subject_id>.json`：`{subject_id, url, search_title, title, year, info, summary, rating, votes, collected_at}`（info 为整块文本，`summary`/`rating`/`votes` 可能为 null）。
- `data/movies.jsonl`（ingest 输出，gitignore）：
  `{subject_id, url, title, year:int|null, rating:float|null, votes:int|null, directors:[], screenwriters:[], actors:[], genres:[], regions:[], languages:[], release_dates:[], runtimes:[], aka:[], imdb, summary, chow_roles:[]}`
  - info 解析规则：按行前缀 `导演: / 编剧: / 主演: / 类型: / 制片国家/地区: / 语言: / 上映日期: / 片长: / 又名: / IMDb:` 拆分，` / ` 分隔；「主演」行去掉尾部「更多...」；无对应行给空数组。
  - 剔除规则（记日志到 `data/ingest_report.json`）：类型含 exclude_type_keywords、info 含 tv_fields 行、无 title。
  - `chow_roles`：各字段中出现「周星驰」则记入，取值 ⊆ [导演, 编剧, 主演, 配音]。
- 三元组（kg/triples.jsonl 与 kg/triples_llm.jsonl 同构）：
  `{head, head_type, relation, tail, tail_type, source}`；type ∈ {电影, 人物, 类型, 地区, 语言, 角色, 主题}；
  relation ∈ {导演, 编剧, 主演, 配音, 类型, 制片地区, 语言, 上映年份, 片长, 评分, 又名, 饰演, 题材}；source ∈ {douban-info, llm-offline, llm-live}。
  extract_llm 产出的行允许附带 `subject_id` 附加键（去重用），图谱加载只消费六字段。
- 别名 `kg/aliases.jsonl`：`{entity, entity_type, aliases:[], note?}`。
- 评测 `eval/qa_eval.jsonl`：`{qid, question, type, gold_keywords:[], gold_relation?, note?}`。

class LLMError(RuntimeError): ...

class LLMClient:
    def __init__(self, cfg): ...          # 缺 key 直接 raise LLMError（中文提示）
    def chat_json(self, system: str, user: str, *, max_tokens: int | None = None) -> dict
    def chat_text(self, system: str, user: str, *, max_tokens: int | None = None) -> str
    # 均走 /v1/chat/completions，response_format json_object 仅 chat_json；

## 5. retriever.py（B 代理负责）

```python
class Retriever:
    def __init__(self, cfg, embedding_cfg): ...    # index_dir 已有索引则加载，否则需先 build
    def build(self, movies: list[dict]) -> None    # 简介分块 + 实体名/别名 两套 FAISS，落盘 data/index/
    def search_synopsis(self, query: str, k: int = 3) -> list[dict]   # {subject_id, title, chunk, score}
    def search_entities(self, mention: str, k: int = 5) -> list[tuple[str, float]]
    def encode(self, texts: list[str]) -> "np.ndarray"                # 委托 embed_client（见 §3.5）
```

> **v2.1 变更**：向量一律来自 `embed_client.EmbedClient(cfg.embedding).encode()`（SiliconFlow API，
> 返回已归一化 float32）。**不要 import sentence_transformers / torch**——本地零深度学习依赖。
> 索引元数据记录 embedding.model + dimensions，二者变更时自动重建索引。

## 6. kg_qa.py（B 代理负责）

```python
def load_graph(kg_dir) -> "nx.MultiDiGraph"    # 合并 triples + triples_llm（存在时），边属性含 relation/source
def understand_question(llm, cfg, question: str) -> dict
# 有 key：LLM JSON 输出 {"entity_mentions": [], "question_type": "fact"|"overview"|"recommend"|"out_of_scope", "target_relations": []}
# 无 key（llm is None）：规则降级——书名号/引号内或别名表命中的词为 entity_mentions，question_type 按启发式（长度<18 且含 是谁|哪部|几年|评分 → fact，否则 overview）

def answer(question: str, *, graph, aliases, retriever, llm, cfg, force_route=None) -> dict
# 返回 {"mode": "direct"|"rag"|"fallback"|"degraded", "answer": str,
#       "evidence": {"understanding": dict, "triples": list, "passages": list, "api_usage": dict | None}}
# fact → 模板直答；overview/recommend → 子图+FAISS 上下文交 llm 生成（要求引用 [1][2]）；
# out_of_scope → 本地礼貌兜底；无 key 时 overview/recommend → mode=degraded，返回检索证据；
# retriever 可为 None（未配 SILICONFLOW_API_KEY）：fact/out_of_scope 不受影响，
# overview/recommend 直接 mode=degraded（passages 为空，evidence 里说明原因）；
# force_route（v2.3，webapp 回答模式用，默认 None 走智能路由）："fact" 强制模板直答 /
# "rag" 强制生成 / "evidence" 只返回检索证据（mode=degraded，零 API）
```
